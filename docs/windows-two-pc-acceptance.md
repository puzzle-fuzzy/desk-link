# DeskLink Windows 双机验收记录

这份记录只适用于当前 Windows x64 候选安装包。它不验证旧协议或旧安装入口；每次验收都必须使用同一份候选安装器和同一份 `windows-acceptance-record.json` 模板。

## 0. 物料与环境

- 控制端：Windows 10/11 x64，安装当前候选包。
- 主机端：另一台 Windows 10/11 x64，安装同一候选包。
- 两台电脑都安装 WebView2 Evergreen Runtime；安装器缺失检查必须通过。
- 记录安装器文件名和 SHA-256，不在记录中写入访问密码、私钥、完整设备 ID、屏幕内容或个人文件名。
- 首先完成一次本机状态检查，再开始配对；中继地址和证书名称必须使用候选包内置的生产配置。

## 1. 同一局域网

- [ ] 主机显示“可被控制”，控制端输入设备 ID 和访问密码。
- [ ] 主机弹出审批窗口；拒绝一次后，控制端能结束当前连接，不会留下“正在查找”或重复会话。
- [ ] 重新连接并批准：首帧、鼠标移动、左/右/中键、滚轮、键盘和快捷键均正常。
- [ ] 主机有两个显示器时，控制端可切换显示器；切换后画面、鼠标坐标和全屏状态仍正确。
- [ ] 在 100%/125%/150% DPI 组合下重复鼠标边缘点击和窗口拖动。

## 2. 不同网络（公网中继）

- [ ] 两台电脑分别连接不同网络，完成同样的配对、审批、首帧和输入检查。
- [ ] 连接状态显示中继路径；视频之外的控制、审批、剪贴板和文件消息仍能完成端到端会话。
- [ ] 断开控制端网络 10–30 秒后恢复网络：主机不显示“服务已停止”，控制端进入重连并恢复新视频流。
- [ ] 重启中继容器后重复一次恢复；不得出现第二个控制端占用会话或旧画面覆盖新画面。

## 3. 权限、窗口和恢复

- [ ] 主机锁屏/解锁、最小化/恢复 DeskLink 窗口后，主机服务仍在线。
- [ ] 睡眠/唤醒后，主机重新可用；控制端不会永久停留在“建立加密连接”。
- [ ] 全屏、适应窗口和 1:1 原始像素模式之间切换；无异常滚动条、黑边或鼠标偏移。
- [ ] 在强制高对比度、键盘 Tab 导航和 WebView2 缩放下，焦点始终可见，中文文案不截断关键操作。

## 4. 剪贴板与文件

- [ ] 短文本、中文、emoji 和多行文本双向复制/粘贴。
- [ ] 单文件发送、接收、取消、失败重试和同名文件不覆盖。
- [ ] 多文件连续发送时，进度、速度、剩余时间和终态正确；断线后可恢复或明确失败。
- [ ] 文件传输期间移动鼠标和发送键盘输入，视频与控制通道不能被阻塞。

## 5. 长稳记录

连续运行至少 4 小时，每 30 分钟记录一次：CPU、GPU、内存、显示帧率、平均延迟、重连次数、传输失败数。结束后导出脱敏诊断报告，只保留事件类型、时间、候选版本和相关性 ID。

## 6. 生成发布证据

在验收完成后，只修改候选模板中的 `checks` 和 `notes`，不要改版本、源码提交或安装器哈希：

```powershell
python scripts/create-windows-acceptance-record.py --operator "实际操作者"
# 按上面的结果填写 dist/windows/windows-acceptance-record.json
python scripts/check-windows-release-ready.py --manual-json dist/windows/windows-acceptance-record.json
```

只有两台真实 Windows 验收、长稳验收、全新账户 SmartScreen 验收和 Authenticode 签名都完成后，readiness 才允许进入正式发布流程。
