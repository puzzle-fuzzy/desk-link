# 连接与共享修复记录（2026-10-21）

## 原因与修复

1. 旧配对记录属于有效的 DPAPI V1 格式，当前解码器只接受 V2，导致读取失败。恢复严格的 V1 读取兼容，未知格式、非法字段与尾随数据仍拒绝；V1 不推断持久连接权限。读取不重写文件，保存仍使用 V2。当前用户原文件的哈希在验证前后保持不变。
2. 共享持续“连接中”的实际网络原因是云主机没有 DeskLink relay 容器、镜像和 UDP 4433 监听，客户端日志持续出现 `relay_connect_timeout`。恢复独立的 DeskLink relay 后，原生应用进入“本机可被连接”。未更改本机代理、路由、防火墙或 TLS 校验。
3. 前端启动时先读快照、后注册监听，可能漏掉主机就绪事件。改为优先订阅，并在窗口可见期间定时及重新获得焦点时核对快照。无变化的快照不重建表单，避免干扰输入与光标；健康的空闲共享状态不再显示诊断警告。

## 临时密码、固定密码与重连复核

同日继续沿三个入口执行流程验证，所有测试身份、密码及 DPAPI 存储均为临时数据；没有更换、清除或读取当前用户的实际访问密码。

本轮修复了以下行为：

- 已处理的临时邀请再次被未知控制端使用时，原生授权层返回明确的加密拒绝，避免控制端仅收到异常断开；已批准设备仍沿既有信任规则连接。
- 固定密码读取或更换的异步结果在离开页面后不再回填密码；返回页面时按当前状态重新读取。
- 固定密码读取失败时提供“重试”，不再一直显示读取中。
- 临时密码在离开密码页后仍按时清除，同时清除包含邀请的二维码内容，不强制切换用户当前页面。
- 取消或新建连接后，旧连接失败触发的迟到快照不能覆盖新会话；同一会话的新状态事件也优先于较早的恢复快照。
- 设备 ID 连接入口的格式错误统一称为“访问密码”，同时适用于临时与固定密码。

验证覆盖固定密码的生成、受保护存储重新加载、首次批准、同码再次连接、更换后旧码失效、关闭后目录不可查询，以及关闭密码后已有信任仍可连接。固定密码首次批准后后续连接不会重复要求批准；未知身份不能借用旧连接进入。

临时密码在同一原生集成链路中覆盖随机密码生成、错码拒绝、正确目录查询、邀请解码、合成审批、非空 H.264 与光标、临时 DPAPI 控制端配置保存 / 加载，以及使用该保存配置在同一本地中继重连后再次出帧。另有在线主机的临时目录 TTL 到期、邀请到期、已处理邀请复用拒绝且不新增信任的独立回归；临时流程相关共 37 项测试通过。
