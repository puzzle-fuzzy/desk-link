# 底座检查与 Windows UI 布局基线

日期：2026-10-21

本轮范围是本地源码、验证与 Windows 页面样式；不处理 GitHub Actions，不进行部署、签名或线上验收。

## 已修复

| 问题 | 调整 | 回归依据 |
| --- | --- | --- |
| 不同限流窗口互相干扰 | 每个账号限流桶保存自己的过期时间，清理不再套用当前请求的窗口 | 短窗口清理不能提前解除小时级限额 |
| 诊断批次半写入后无法重试 | batch、events 和保留期清理放入同一 SQLite 事务 | 第二条事件失败后无残留，重试完整写入，随后正确去重 |
| FFI 主机首次 join 可能永久等待 | 首次和重连都使用既有 10 秒 join 超时 | 本地中继接收连接但不 ACK 时有界返回并关闭资源 |
| 可靠流写入被取消后仍复用半帧流 | 部分帧取消或失败后明确关闭连接，交给既有恢复流程 | 未消费旧消息时取消后必须断开，不能继续向损坏流发送 |
| 恢复关键帧分片乱序时误删本帧已收数据 | 只丢弃更旧的未完成帧，保留当前恢复帧和更新帧的分片 | 按 2、1、0 顺序投递分片的确定性回归；集成夹具使用确认屏障后再投递下一增量帧 |
| 默认控制页收不到及时的主机审批提示 | 比较主机呈现字段后按需刷新，忽略纯时间戳心跳 | 新增、撤回、身份变化和错误状态会刷新，时间戳不重建画布 |
| 审批重绘、忙碌与过期时焦点可能逃逸 | 焦点回到拒绝按钮或弹窗容器，Tab 保持闭环；过期动作持续禁用 | 焦点策略与审批状态回归；浏览器模拟验证默认拒绝和反向 Tab |
| 进入账号页时直接拆除远程 DOM | 所有页面替换前执行现有输入和展示资源清理 | 验证 loading / account 两条提前返回均先清理，返回工作区重新绑定 |
| 单列连接区网格被压缩后内容重叠 | 按内容高度布局，由工作区滚动 | 浏览器模拟中连接表单底部与最近设备面板不再交叠 |

可靠流取消采用明确断开连接的保守语义，不承诺取消后当前文件任务自动成功；继续使用既有偏移、哈希校验和显式重试流程。不新增 relay wire 版本或特殊 reset 协议。

## 视觉剥离

删除旧 `styles.css` 和 `product-ui.css` 的多轮主题。保留布局、响应式、原生控件与功能性可访问样式，移除配色 token、品牌字体、字号层级、圆角、阴影、渐变和装饰动画。同步清理 DESIGN 与旧样式模板，避免下一次改版继续沿用旧主题。

结构分为 `styles/layout.css`、`styles/base.css`、`styles/interaction.css`。菜单和审批使用系统色实心表面；画布、光标和二维码保留必要对比。设置使用可见的原生 checkbox 并有明确名称。原装饰骨架改为可见的加载文字。

前端生产 CSS 从 128.48 kB 降为 46.90 kB（构建输出，gzip 从 23.25 kB 降为 8.78 kB）。新的视觉风格尚未设计。

## 后续基础工作

1. FFI 已连接阶段的网络发送与同步 shutdown/join 需要统一取消边界：命令分支内的发送可能阻塞取消。应先补充背压 / shutdown 回归，再单独调整 worker 退出策略；Apple 发布前须完成。
2. `main.ts`、`controller.ts` 和 Windows runtime 体量较大。后续按账户、审批、传输、远程展示的所有权逐步拆分；每次只移动一个边界，保留已建立的状态机与回归，避免同时改框架。
3. 当前本地总验证入口 `scripts/verify.sh` 仍混合原生、前端和历史文档扫描，且未覆盖两个 Bun 服务。宜独立建立不访问线上的本地验证入口，再按平台组合原生验收。
4. 新 UI 先确定信息架构和主要交互，再设计视觉层；继续保留主机批准、纯文本剪贴板、文件确认、队列暂停恢复和输入释放边界。

## 同日后续：UI 重设计

按后续要求完成新的 Windows UI：连接设备与共享此设备并列主导航，设置留在次级入口；使用浅色中性表面和青绿强调色，保留暗色、高对比度及键盘操作。连接页保留 ID、密码与最近连接，共享页保留本机 ID、复制和密码操作，高级参数默认折叠。
