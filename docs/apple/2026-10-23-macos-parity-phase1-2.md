# macOS 界面与稳定性对齐：第 1、2 项

日期：2026-10-23。范围为现有 SwiftUI macOS 客户端与共享 Rust / Apple 桥接；不改变 Windows 的界面或发布版本。

## 已实现

- 连接设备、共享此设备、设置与诊断三大常驻导航；共享与设置在正常页面展示。
- 连接阶段依据 Rust 的实际事件推进，包含耗时、取消、失败重试及原目标保留。Noise 完成后才提示等待主机确认。
- 最近设备展示设备 ID、别名和上次连接。兼容旧版钥匙串 JSON；旧记录用公钥摘要区分，重命名不改变凭据，移除需要确认。
- 会话支持适应窗口、1:1 物理像素、独立浏览拖动/滚动、原生全屏、Esc 退出、工具栏自动收起和顶部唤出。
- 视频渲染、远端光标和输入采用同一套坐标几何，考虑 Retina；浏览模式不发送远端键鼠。
- 切换模式、失焦、断线、窗口销毁和全屏转换释放按键。全屏进入动画期间退出会延后完成必要的窗口清理。
- 可恢复错误保留重连 runtime；真实新握手边界允许主机重启后复用流 ID；重连期间保持会话页面和缩放状态。
- 旧回调、旧流和旧解码会话输出不能覆盖新会话；异步解码允许显示落后于最新提交、但仍是最新可用的帧。
- Rust/C 事件枚举同步，并增加 C 编译器校验布局的门禁。Mac 被控端对暂不支持的传输请求有界回复 Unsupported，不因未知事件结束会话。

## 验证

最终自动门禁：

```sh
cargo clippy -p desklink-ffi --all-targets -- -D warnings
./scripts/verify-macos-runtime.sh
./scripts/verify-ios.sh
```

- Rust：59 项（会话状态机 15、FFI 42、端到端恢复 2）。
- Apple 共享核心：33 项。
- macOS：56 项。
- iOS：20 项单元测试、2 项 UI 测试；未签名设备构建和模拟器测试通过。
- 合计 170 项，不重复计算 iOS 验证脚本再次执行的共享核心测试。
- 验收隔离调整后，再次执行 macOS release bundle 构建与 56 项 macOS 测试，通过。

原生交互使用独立 DEBUG 验收应用，合成 2560×1440 图案。已检查光标、缩放、浏览拖动、原生全屏、自动收起及 Esc 返回。该程序不连接远端设备；断开和退出后也保持验收视图，避免载入用户连接列表。Release 二进制不包含 `DESKLINK_SESSION_ACCEPTANCE` 入口。

运行验收应用：先 `swift build --package-path apps/macos --arch arm64`，将 debug 可执行文件放入独立 bundle 并以单独 bundle ID 签名，然后设置 `DESKLINK_SESSION_ACCEPTANCE=1` 启动。不要把验收二进制作为正式安装包。

日志与实际安装结果位于被 Git 忽略的 `dist/macos/`：

- `phase1-2-verification.log`、`phase1-2-ios-verification.log`、`phase1-2-clippy.log`。
- `phase1-2-final-package.log`、`phase1-2-final-macos-tests.log`。
- `installation-report.json`：源提交、分支、已安装文件哈希、签名、启动和授权状态。
- `backups/before-phase1-2-20261023-211225/`：更新前的应用和安装包，保留回退能力。

## 安装与验收边界

本机构建使用 ad-hoc 签名，未进行 Developer ID 签名或公证。更新后，macOS 可能要求用户重新授权钥匙串访问及共享权限；保留原有身份与连接记录，不删除或绕过系统授权。

本机最终启动验收已完成：用户自行完成钥匙串授权后，已安装应用进入本机模式，连接、共享、设置与诊断三个页面均能正常切换并响应；旧版最近设备记录仍可读取。验收后应用停留在连接页面。本机屏幕录制和辅助功能尚未授权，未修改这些权限；它们仅在共享此 Mac 时需要。

真实 Windows 远端的长时间控制、断网/主机重启、多显示器和输入法仍需要对应实机回归；本轮合成会话交互与自动测试不能替代这些验收。

后续项目保持规划顺序：输入法与快捷键完善、画质/多屏和剪贴板、声音/文件、Mac 被控端设备 ID 和密码、诊断和发布完善。当前远端光标显示通用箭头，任意光标位图需要后续协议能力支持。
