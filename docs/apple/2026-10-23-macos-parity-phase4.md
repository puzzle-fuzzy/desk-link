# macOS 功能对齐：第 4 项

本项承接第 1～3 项，补齐 Mac 控制现有 Windows 主机的系统声音与双向文件传输。不修改 Windows 发布程序或公网 relay，不升级线协议。

## 已实现

### 系统声音

- 工具栏“远端声音”提供开启/关闭、音量和本机静音。默认关闭；收到真实远端状态确认后才允许本机播放。
- Rust 静态链接 vendored Opus，支持现有 Windows 的 48 kHz、单声道、10 ms Opus，以及过渡版本 PCM。解码后固定输出 480 个 s16 LE 样本。
- 单包缺失使用 Opus FEC；重复、迟到、过期或损坏的数据报不能结束视频会话。声音错误只停用声音。
- Swift FFI 入口对 PCM 使用有界邮箱并丢弃长时间等待主线程的包；原生播放器另有 100 ms 有界队列。旧会话、旧序号、关闭后的数据不能继续播放。
- AVAudioEngine 仅播放，不打开麦克风。音频设备失败会停用并提示重新开启；同一状态的重复开启使用已认证的真实远端状态确认，避免等待不存在的重复通知。

### 文件传输

- 工具栏“文件传输”打开独立面板。发送使用原生多文件选择器；多文件按顺序逐个发送，最多保留 32 个等待文件。
- 获取远端文件时，先选择本机保存文件夹，再请求远端用户选择文件。只接受精确匹配当前请求的邀请；未经请求的文件会被拒绝。
- 展示准备、等待确认、发送/接收、校验、完成、失败和取消状态，以及字节进度、重试、暂停/继续队列、传输记录和“在访达中显示”。失败或取消后暂停后续队列。
- 单文件最大 256 MiB，分片最大 48 KiB。文件内容使用原有独立加密可靠通道；文件 IO 独立于输入、视频和音频接收循环。
- 源文件及接收目录通过文件描述符固定，拒绝非法文件名和符号链接终点；先写私有临时文件，完整大小与 BLAKE2s 校验通过后原子发布，同名文件不覆盖。
- 取消、断线、超时和校验失败会清理未完成文件。旧请求、旧连接或旧选择器返回不能向新会话发送文件；同 stream 的屏幕切换仍可取消当前文件任务。
- 重试使用新任务、从头发送。当前不保留跨应用重启/跨重连的断点恢复记录；断线清空未开始队列，避免自动发送到另一台设备。

超时与 Windows 现有行为对齐：远端接收确认 120 秒、远端文件选择 300 秒、无传输进展 60 秒、单次可靠发送 30 秒、最终保存确认 60 秒。超时恢复任务按钮，不主动结束远程画面连接。

## 代码边界

- Rust：音频解码及状态、独立文件 actor、安全文件 IO、4 个 stream 绑定 C API，以及 PCM 事件 15 / FILE 元数据事件 16。
- Apple 共享层：`ControllerMediaBridge` 管理声音状态和文件任务关联，旧回调代际仍由连接 Bridge 隔离。
- Mac：`RemoteAudioPlayer`、`MacFileTransferController` 和会话声音/传输界面。
- Apple 不再将旧 raw AUDIO / TRANSFER 事件复制到界面队列，避免大文件分片形成无用的主线程积压；C ABI 保留这些事件供其他调用者兼容。
- Mac 被控端的系统声音采集与文件服务未在本项实现，仍属于后续被控端能力建设。

## 自动与原生验收

最终门禁通过：

```sh
./scripts/verify-macos-runtime.sh
./scripts/verify-ios.sh
```

同时通过 `cargo clippy -p desklink-ffi --all-targets -- -D warnings`，两份 C 头文件同步、C/Rust 布局及枚举校验继续通过。

- Rust 85 项：状态机 15、FFI 68、端到端恢复 2。
- Apple 共享核心 66 项，含本项新增 18 项声音/文件状态测试。
- macOS 99 项，含本项新增 18 项原生音频与文件队列测试。
- iOS 20 项单元测试与 2 项 UI 测试；设备未签名构建和模拟器测试通过。
- 合计 272 项，不重复计算脚本内再次执行的共享核心测试。

Rust 测试包含真实 QUIC + Noise 加密链路上的 C API、Opus/PCM、损坏音频仍保持连接、双向文件往返、大小/顺序/哈希、超时/取消、队列饱和和请求关联。原生测试包含音频离线渲染的非零波形、有界缓冲和迟到回调，以及异步文件选择跨连接/跨绑定隔离。

独立 DEBUG 原生验收程序使用内存剪贴板及公开测试文本，不连接真实远端或读取用户钥匙串。已验证：

- 显式开启后短测试音进入原生播放，界面显示“正在播放”；音量降低、静音和关闭声音可响应。
- 原生 NSOpenPanel 选择自建 63 字节文本，显示发送进度和完成。
- 原生文件夹选择器选择自建临时目录，显示接收完成及访达入口；生成文件与源文本逐字节一致。
- Release 不包含 DEBUG 验收入口或临时目录标记。

## 实际安装与 Windows 验收

已安装 `/Applications/DeskLink.app`，与构建产物哈希一致，原身份和最近设备保留。正式应用启动、跳过账号登录进入本机模式、使用旧记录连接 Windows 均已验证。

真实 Windows 会话收到声音开启/关闭确认；远端没有持续音频内容时，本机显示等待声音。本轮没有将“人工听音确认”记为通过。修复了初始声音暂不可用、随后恢复可用时旧错误提示没有清除的问题，并补充回归断言。

真实文件发送使用同一份自建公开测试文本。客户端进入等待远端确认；本次未取得 Windows 端接收确认，随后正确超时、显示失败和重试入口，视频连接保留。因此真实 Windows 双向文件发布完成仍待实机配合验收，不能用本地加密往返或隔离界面测试替代。

验收结束会关闭声音、断开验证连接，保留应用在连接页面。无私人文件传输、无账号/权限变更、无旧身份或连接记录删除。

## 构建与产物

Opus 使用源码静态编译，构建需要 CMake，应用运行不依赖外部 Opus 动态库。`scripts/apple-build-tools.sh` 优先使用环境变量 `CMAKE` 或系统 CMake，本机也可使用已准备的 `.tools/cmake/cmake/data/bin/cmake`；此本机构建工具目录不进入 Git 或应用包。

Opus 与 opus-head-sys 的实际许可保留在唯一源文件 `apps/apple/Resources/ThirdPartyNotices.txt`，已同时纳入 Mac 与 iOS 包资源。

- 安装包：`dist/macos/DeskLink-macOS-arm64.dmg`，包含 `/Applications` 链接并通过 hdiutil 校验。
- 安装与验收记录：`dist/macos/installation-report.json`，含最终哈希、测试及实际验收范围。
- 旧版备份：`dist/macos/backups/before-phase4-20261023-234509/`。
- 最终日志：`phase4-verify-macos-final.log`、`phase4-verify-ios-final.log`、`phase4-rust-lib-tests.log`、`phase4-session-acceptance.log`，位于 `dist/macos/`。

本机仍为 ad-hoc 签名，strict codesign 校验通过，未进行 Developer ID 签名或公证。源码保留在当前分支工作区，未提交或推送。
