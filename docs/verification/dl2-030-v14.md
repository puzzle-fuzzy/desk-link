# DL2-030 协议 14 文件任务验证记录

本记录区分本地真实磁盘/网络夹具与设备验收；DL2-030 主验收仍未完成。

## 已接通的 Windows 行为

- Host 与 Controller 共用已认证 peer 绑定的文件 actor；扫描、散列、磁盘写入、确认和任务恢复均在独立有界 worker，媒体/输入循环只处理有界消息。
- 协商后的单文件预算最高 1 TiB、任务 16 TiB、100 万项；旧 FileOffer 保持 256 MiB。文件队列沿用原有确认与 DPAPI 保护，超过 4 GiB 的大小和偏移全程 u64。
- 目录保留空目录及中文长名称，逐项发送；同名冲突不覆盖。磁盘发布前实际全量验证；每个 ACK 都在数据和块证明持久化之后。
- 暂停/恢复、取消、断线及磁盘 actor 销毁重建、逐项与整任务重试均保留任务身份。远端发起重试需要源端重新确认；不自动复用先前取消的授权。
- 源索引以块证明定位恢复点。可靠非零 NTFS USN 未变化时可直接复用；没有可靠变化令牌时必须实际重验源内容，且显示校验进度、支持取消。不能把所有文件系统描述为免前缀重验。
- Windows 所有目录、缓存和暂存操作以已打开父目录句柄相对执行；拒绝重解析点、硬链接写目标、ADS 和越界。最终文件使用 create-only 句柄重命名发布，取消按拥有的文件句柄清理。
- 原生选择/确认窗口归属当前连接，取消和停止关闭其精确窗口；IPC 等待方退出不会提前释放仍在运行的选择器 single-flight。
- UI 显示扫描/散列/已发送/已持久确认/最终校验阶段，字节十进制字符串和 BigInt 不丢精度。最多 64 项、100 ms 合并更新；真实加密保存完成前只显示正在保护。

## 扫描失败与发布索引切片

扫描结果以成功记录的稳定前缀和失败记录尾部持久保存。文件打不开、超单项预算、坏名称/重解析点、无法枚举的子树分别保留安全重试范围；有效兄弟项继续。重试先验证原清单，再重扫失败范围；成功项身份不变且已确认数据不重发。派生磁盘索引按完整键处理碰撞，失败范围重叠也只计一个活动失败；临时槽最多两倍条目预算，整理后只有活动失败进入正式清单。旧清单读句柄贯穿验证/复制，新清单 writer 同步后持原句柄发布；缓存混合记录和错配范围拒绝。

源目录根（包括空根）、源目录项及接收目录叶子在握手期间持有祖先/叶句柄，拒绝种类替换和重解析点；不把正常修复子文件产生的目录 mtime 变化误判成内容变更。缓存、接收文件分卷时分别预留实际增长空间，同卷合并预算。

实际清单读取/复制/发现/失败槽整理/发送最多六遍记录工作，以严格单调且有界的 activity 表示；与项目数、已发送字节及进度百分比分开。发布前已经实际全文验证的 ledger 可在原写句柄仍持有且 NTFS close USN 已 sealing 后，用固定 128 KiB 缓冲复制块证明为 published index。Indexing 独立计数真实块证明记录，避免大索引复制被误判为停滞；用户提示正在完成文件保存。无法 sealing 时保留全文复验路径。

最终整合门禁的实际计数及哈希保存在外部 evidence 汇总；本文件不回填动态提交 SHA，避免为记录证据而改变已验证源码。
