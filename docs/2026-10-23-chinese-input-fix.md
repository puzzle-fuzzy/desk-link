# 控制端中文输入修复（2026-10-23）

用户已在两台真实 Windows 电脑安装 2026-10-21 测试包，反馈被控端本地中文正常、控制端无法远程打出中文。本轮围绕这一输入问题修复，不调整页面设计。

## 原因

远程画面原先是可聚焦但不可编辑的 DIV，仅监听 `keydown` / `keyup`，并对已识别按键调用 `preventDefault`。没有用于本地输入法的可编辑焦点，也没有处理组合输入的最终文本。输入法产生的 `Process`、组合候选和确认内容因此不能形成远程文本输入。

原生端已支持现有协议中的 `KeyCode::Character`，通过 UTF-16 和 Windows `KEYEVENTF_UNICODE` 注入文字；缺口在控制端的事件与焦点处理，不需要更改网络协议或系统输入法设置。

## 修复范围

- 在远程画面内增加不可见的可编辑输入承载，点击远程画面后可以使用控制端本地输入法直接输入。
- 区分输入法组合、最终提交与快捷键；候选期间的确认、编辑和取消按键由本地输入法处理，避免远端收到多余按键。
- 去重同一次组合结束后的输入事件，普通字符也使用单一路径提交。
- 将文字与鼠标 / 键盘操作放入同一发送队列，保持中文提交与后续回车等操作的顺序。
- 文本 IPC 增加可选的 `streamId`，旧“文字”面板调用仍可省略；排队和执行时均检查所属视频流，丢弃过期提交。
- 失焦、断线、离开远程画面时清除输入法临时内容，避免迟到提交进入新连接。

## 验证边界

使用合成输入事件检查前端组合与键盘时序，使用原生输入记录检查中文、中文标点、emoji 与扩展汉字的 UTF-16 参数，不向用户当前窗口注入文字。原生协议、加密动作和输入记录相关 17 项测试通过；Tauri 库 82 项测试通过。

前端 232 项测试与 TypeScript / Vite 构建通过，其中新增 19 项覆盖 IME、实际输入绑定及文本队列顺序。覆盖正常点击 / 鼠标捕获释放后的中文输入、候选键隔离、组合结束尾事件去重、相同词连续提交、普通英文单发、全屏 Esc、浏览模式 Esc 返回后的编辑焦点、失焦后重新聚焦时的迟到旧事件，以及中文确认后回车 / 鼠标操作的发送顺序。相关 Rust Clippy、格式与补丁空白检查通过。

真实双机输入法候选框、具体第三方输入法和目标应用的输入表现仍由更新后的测试包复测。现有测试不会替用户修改输入法或在私人桌面输入内容。

## 设备复测

先更新控制端。连接后点击被控端记事本或普通文本框，用控制端中文输入法输入“中文输入测试，连续输入你好你好”，检查候选确认不会额外发送空格或换行，再检查中英混输、候选退格、Esc 取消和确认后的回车。断线恢复后，未确认的旧拼音不应自动出现在远端。
