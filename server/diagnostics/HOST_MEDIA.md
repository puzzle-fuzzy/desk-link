# Pinned host media diagnostic contract

The first accepted typed host-media event is pinned to producer commit
`a599246535b73f57e0425cbbfd18c7156e050bba`:
`DiagnosticEvent::HostMedia(HostMediaDiagnostic::CursorSend)` in
`apps/windows/src/diagnostics.rs`. The serde `kind: cursor_send` fallback written
to stderr is a different representation and is not the cloud event contract.

The product encoder emits exactly these fields for `source: host`:

```json
{"schema":1,"timestamp_unix_ms":1,"level":"warning","event":"host_cursor_send","stream_id":7,"send_attempts":2,"send_errors":1,"disabled":true,"reason":"capability_or_size"}
```

The timestamp above is illustrative. Validation uses the existing accepted time
window. `stream_id` is a positive safe integer; both counters are nonnegative
safe integers and errors cannot exceed attempts. `disabled` is a boolean,
including false for typed snapshots; the reason is the fixed
`capability_or_size` enum. The three new fields are accepted only for this exact
event. Extra legacy fields, raw error/identity fields, unknown reasons, a
controller source and the stderr representation are rejected. Existing safe
integer limits remain in force: Rust u64 values above 2^53−1 are not silently
rounded into accepted data.

The store needs no schema migration: it already retains the entire validated
payload and deduplicates events/batches. A valid mixed batch containing legacy
host events and the pinned cursor event is accepted atomically. Invalid signed
schema data still returns a permanent 400; this change does not introduce a
partial-accept/drop policy or change the desktop uploader's retry behavior.

Analysis records one `cursor_lane_disabled` warning when a valid host cursor
snapshot reports disabled with positive send errors. It retains independent
healthy-video evidence, does not sum snapshots across peers or shared stream
IDs, and does not feed cursor counters into video loss or delivery metrics.
`send_errors` counts local send calls returning errors. Quinn may evict queued
datagrams while returning Ok, so neither delivery nor those evictions can be
inferred from this event. The fixed reason does not distinguish unsupported,
disabled or oversized transport conditions more finely.

## Regression and boundaries

`fixtures/host-media-cursor-producer.json` is generated by compiling and calling
the pinned Rust product encoder, not by translating its format into TypeScript.
It records commit/source blobs and hashes, compiler version, and raw JSONL for
normal, false, safe-integer-boundary and u64-overflow cases. The generator uses
an isolated local harness and the repository's locked dependency versions;
see the fixture README for its command and the harness's unrelated-type stubs.

`src/host-media-contract.test.ts` signs those events with an ephemeral synthetic
Ed25519 key, verifies them through the production validator, submits them through
the production app/store, checks exact stored payloads and duplicate receipts,
then reads the actual analysis rows. Negative cases check event-scoped fields,
bad types/reasons/source, missing keys, unsafe integers and signature tampering.

The DL2-045 listener event is pending its producer SHA and is not pre-authorized
by this schema. Product observer binding, GUI/export, real hardware and the rest
of DL2-044 remain separate acceptance work. This local contract test does not
establish that the product currently uploads these events. Uploaders must treat
permanent invalid-schema responses according to their own reviewed retry policy;
that lifecycle is not proven by server acceptance of this pinned event.
